# Magica Tracker

A calm, single-page tracker for projects, their tasks and sub-tasks, linked resources, and a backlog. Everything lives in the browser (IndexedDB, or `localStorage` where IndexedDB isn't available). There is no server and no account. Export and Import are the backup, and exported files are also how a team shares its work.

## Using it

Open `dist/index.html`. It works straight from disk (`file://`) or behind any static server, such as Caddy on the homelab. It makes no network requests.

**Load sample data** (top left) fills the tracker with magic-themed projects, tasks, deadlines and backlog ideas, dated around today, so you can see how it looks when lived in. It also adds four sample teammates (Alice, Bram and Dara with files, Chiyo without one) so Team, View as and the Observatory have something to show; they go in your team, never in your own data or exports. **Wipe sample data** removes them again, teammates included. Every sample id starts with `sample-`, so your own projects and tasks are never touched, even when they sit side by side.

The top bar switches between **Overview** (projects, tasks, backlog) and **Timeline** (a month calendar of deadlines, events and days off, with today circled). Clicking an item on the Timeline opens it in Overview. The top bar belongs to these two views only; the screens the orb opens have "← Your tracker" at the top instead, so nothing there sends you home unexpectedly.

Everything else is behind the **orb** in the bottom-right corner, so the everyday views stay quiet. Opening it shows a column of round buttons: from the top, **Board**, **Team**, **Observatory**, **Highlight**, **Time log**, **Allocation**, **Settings**, Overview, and Search nearest the orb. On a phone they're a row that wraps onto a second line, so every circle stays on screen. Hovering (or focusing) a section lists its common actions, and hovering an action explains it beside the list; Overview and Search show a short note on what they do. Choosing an action opens that screen and briefly rings the part to use ("Start here"). On touch, the first tap on a circle shows its actions or note and a second tap opens it. **⌘K** (Mac) or **Ctrl+K** (Windows, Linux) opens a search palette over places, those actions, people, projects and open tasks. Within each group, names that match come before things that only mention the words.

| Key | Does |
|---|---|
| `n` | Focus "Add a task" in the current project |
| `b` | Capture an idea into the backlog |
| `t` | Switch between Overview and Timeline (on those views) |
| `Space` | Toggle the focused task |
| `/` | Focus the project filter |
| `Esc` | Close whatever is expanded |
| `⌘K` / `Ctrl+K` | Search: go to a place, an action, a person, a project or a task |

## Developing

```sh
pnpm install     # also points git at .githooks/
pnpm dev         # Vite dev server
pnpm test        # Vitest specs for src/core
pnpm build       # writes dist/index.html
pnpm check       # typecheck + tests + build + fail if dist/ is out of date
```

**`dist/` is committed.** It is the product. Run `pnpm build` before committing changes to `src/`. The pre-commit hook rebuilds and refuses the commit if `dist/index.html` changed. Never edit `dist/index.html` by hand.

## Layout

```
src/core/      pure rules, no DOM: schema (Valibot), completion, staleness,
               merge, migrate, validation, ops, url/time helpers
src/storage/   IndexedDB (idb.ts, data.ts) with localStorage fallback (local.ts),
               debounced save, cross-tab sync; the team record (team.ts)
src/ui/        Preact UI: store (commit()), actions, styles.css (Tailwind CSS v4)
  shell/       top bar, banners, dialogs, toast, the orb and search palette: around every view
  views/       one folder per view (overview/, timeline/, settings/, team/,
               member/ for View as, observatory/, board/, allocation/, timesheet/,
               highlight/) with the components only it uses
  components/  components shared across views
tests/         Vitest specs for src/core and src/storage
```

UI conventions (folders, Tailwind setup) are written up in `CLAUDE.md`.

Every change goes through `commit()` in `src/ui/store.ts`. It applies the completion rule, re-renders, and saves after 300 ms.

## Decisions beyond the original plan

- **Date, not a greeting.** Overview's heading is today's date. Timeline's heading is the month. Export and Import sit in the top bar next to the view switch.
- **Quiet by default.** No empty-state sentences. The Needs attention panel is hidden when nothing qualifies, and shows only the 3 most pressing items until you ask for more ("Show N more"). The theme carries the calm.
- **Look.** Inter (bundled, Latin subset, 48 KB) in cards on a soft page. The top bar and page structure are unchanged from the first design. Under the date ("Sunday, 4 Oct"; the Timeline heading reads "October, 2026"), an "At a glance" board: four numbers (open tasks, in progress, waiting, overdue) divided by hairlines, with the allocation bar along its bottom. Only overdue carries a colour, and only when it isn't zero. Boards are spaced generously, with quiet labels above them.
- **At a glance opens up.** Clicking a number (other than a zero) opens the list of what it counts inside the card, between the numbers and the allocation bar: open tasks most pressing first, in progress, waiting (longest first) or overdue (projects and sub-tasks too, most overdue first). Each row says why it counts (a deadline, Urgent, High, how long it has waited, sub-tasks done) and its allocation, and opens its task. Five show at first, then "Show N more". Clicking the number again, or ×, closes it. View as shows the same card, so the two never drift apart; there the rows are read-only.
- **Deadlines** (`due`, a calendar day like `"2026-10-03"`) are optional on projects, tasks and sub-tasks. They are set with a small themed calendar (a popover: arrow keys move by day and week, Page Up/Down by month, with Today and Clear) and compared in local time. A deadline is *approaching* when it is 3 days out or closer (`DUE_SOON_DAYS`, fixed). Approaching and overdue deadlines turn amber and appear in Needs attention. A task listed there for its deadline isn't listed again as urgent or stale. Overdue shows as a count of days ("3d overdue"). Once the item is done its deadline stops being owed, so a past one reads as time ago ("7 days ago"), and so does a past start date. In the Timeline, a day cell shows its 3 most urgent deadlines (unfinished first, then project deadlines, then by priority) and "+N more", so every week keeps one height. Clicking a day opens all of them in a side panel with details and quick actions.
- **Priority** is optional on tasks: low, medium, high or urgent. Open tasks are ordered by priority, then nearest deadline, then the order added. Open urgent tasks appear in Needs attention.
- **Allocation** is optional on tasks: a percent of your capacity for one period (stored as `effort`). Settings → Allocation → **Show it in** switches between **Percent** and **Hours**: in hours, 100% is **40 hours a week** (80 a fortnight), and anything past it is past 100%, as in percent. It is only how allocation is shown and entered; the data stays in percent, so switching never changes it (an allocation entered in hours is kept to a fraction of a percent: 10h of an 80h fortnight is 12.5%). The unit is how you read everyone's allocation, your team's too, each by their own period. The period is a **week** or a **fortnight** (Settings; fortnight by default). Weeks start on Monday; fortnights count from Monday 1 January 2024, so everyone's line up. By default a task's whole share lands in the period its **deadline** falls in. An optional **start date** spreads it evenly by day from the start to the deadline, for work you want to begin early. Work that is overdue, or has no deadline, counts now. Every task in an active project adds into the Allocation bar on the Overview, which runs up to your **limit** (Settings, 100–300%, 150% by default). Up to 100% fills in the theme's primary colour; overload past 100% fills in its highlight, and past the limit the note says so. The period is fixed, so **finishing a task doesn't free its share**: it stays in the period it counted in on the day you finished it (late or undated work stays in the period it was finished in), even if its project is archived later. The note says how many of the period's tasks are done. Marking a project done, or archiving it, frees only the shares of tasks left open in it.
- **Status.** Every task has one: **To do** (the default), **Working**, **Waiting** or **Done**. It is set in an open task's **More details**, or by dragging its card on the Board. Waiting asks what on (a person, a meeting, evidence) and remembers since when; for work that moves at meetings, most stops are waiting on someone rather than a real block, so there is no separate Blocked. Ticking a sub-task of a To do task makes it Working, ticking the last one makes it Done, and the checkbox is still the quick way to Done. A row shows Working as a quiet pill, and Waiting as an outline that hides the other chips until it moves again. Waiting tasks appear in Needs attention (longest waiting first) and in the numbers; Working is what "in progress" counts.
- **More details** on a task (and a project) folds away the fields most tasks don't need, closed until you open it. Inside, they are a row of small tiles (two by two on a phone), each showing its value or "+ Add"; clicking a tile opens its editor under the row. The tiles: the task's **status** (and what it waits on), **I may be escalated** (with by whom and why), **Definition of done** and **Related people**, all optional free text. Folded, its header lists what's set. "I may be escalated" is the member's own early warning to their leader that another team's workload may escalate them; it is dated, and shows in the Observatory.
- **Events, leave and holidays** sit on the Timeline beside the deadlines, and belong to no project. **+ Add** in the Timeline's header (or "Add to the calendar" in search) opens today with a form; every day's panel has "Add an event, leave or a holiday" too. An **event** is a task without a project: an optional time, a last day for one over several days, an optional allocation and notes. It is an outlined chip leading with its time; it ticks done from its checkbox in the day panel; unfinished past its last day it turns amber and joins Needs attention ("8d overdue"); and **Move to a project…** turns it into a task there (its date the deadline, its last day the spread). Its allocation counts like a task's, in its own **Events** group on the Allocation screen; it never touches the timesheet. **Leave** and **holidays** stripe their days and name them on the calendar (View as shows a member's too). They lower a period's capacity (below) and count toward the month's timesheet; the form says how many working days one takes.
- **Working days and the Time log.** The finance timesheet is a monthly balance: each calendar month's working days must be accounted for, given to projects in whole days or taken as leave or a holiday. Which day went where doesn't matter, only that the month adds up. Settings → **Working days** sets **Tracking from** (nothing is kept, and nothing flagged, until it is set) and the **working weekdays** (Monday to Friday by default; switching on a weekend day is allowed, with a toast that says “Working weekends? We don’t do that here.” and an Undo). A month's working days are its worked weekdays from the start date on. The **Time log** (from the orb, or search) shows one month: its working days, given to projects, leave and holidays, and what is still to go (or over), with a block per day; a whole-day stepper per project, grouped by domain (a project marked done or archived stays through the month it ended in; after that it shows only where it has days, and joins through "Other project"), and **Copy** last month's split; the month's days off; and every earlier month with whether it balances. A month is flagged in Needs attention ("October timesheet · 2 days to go") once it is past and doesn't add up, or is over, or is short with its last working day 3 days away or closer. A project's More details gets a **Timesheet** tile: this month's days and all of them. Days are stored on the project (`timesheet`, one entry per month), so deleting a project takes its days with it.
- **Cost centers** are what the timesheet charges days to, for finance. They have nothing to do with domains: each has a code, a name or both, and a project has one or none. Everything about them is on the **Time log**. Its **Cost centers** panel (or "Cost centers" in the orb or search) lists them with the shown month's days charged to each, then days charged to none; each opens to its projects, "+ Add a project", Rename and Delete, and **New** adds one. Under each project's name in the Projects panel, a small picker says where its days that month are charged and changes it. From this month on, picking one sets the project's cost center, so this month and later ones follow; for a month already over it re-charges that month alone, as a correction. Otherwise a month's days keep the cost center they were charged to when given: changing a project's cost center never moves earlier months. Leave and holidays are never charged, and the panel says so. The month's line over the blocks ("25 of 22 · projects 23 + days off 2") opens the bar by cost center: the blocks regroup, a shade of the bar's colour per cost center, then days off in the accent's stripes, with any days past the month ringed in the highlight; below, a card per cost center lists its projects and days, and one lists the leave and holidays, not charged. The cards scroll sideways when there are more than fit. Open, each run of blocks is labelled with its days and cost center. Clicking a run (even before opening) or a card picks that cost center: its run sits in a tinted box with the accent's outline, and its card is outlined and scrolled into view; clicking it again lets go. Deleting a cost center in use asks first: its projects are left without one and its days are charged to none. On the Overview, a project's More details does the same for that project: the **Cost center** tile picks one, and the **Timesheet** tile sets this month's days with a stepper and lists earlier months with where they were charged.
- **Capacity.** Leave and holidays on worked weekdays lower a period's capacity: a fortnight of 10 working days with 2 off has its 100% at 80%, and its limit lowered the same way (150% becomes 120%). The allocation bar's tick sits at the capacity and its heading counts the days off; the Allocation chart marks a lowered capacity across its column, and the period's detail says why. Nothing about the timesheet changes allocation otherwise.
- **Board** (from the orb, or "Board" in search) shows every active project as a lane and its tasks in columns: To do, Working, Waiting, and Done for the last 7 days. Lanes follow your project order; a dot marks one with something overdue or urgent (deeper) or due within 3 days. Under the title, today's date; then an At a glance card like the Overview's: overdue, due in 3 days, urgent, and waiting (with the longest wait). Cards are titles only. Moving is by dragging: hold a card (a long press on touch; a quick swipe still scrolls) and drag it to another column, or up and down to reorder; the other cards slide aside to make room, and the order is the project's own task order. A card moves within its own lane only, and the other lanes fade while one is held. While a card is held, the column it would land in opens a gap marked "• Drop here", and the lane's other columns show a quieter "Drop here" at their foot; the held card hangs just beside the pointer so the gap stays in sight. Dropping one in Waiting asks what on. Clicking a card opens its details (status, deadline, priority, sub-tasks, notes, what it waits on) with a way into the project. On a phone each lane is a short list grouped by status. It is opt-in by being there: nothing on the Overview changes for people who never open it.
- **Weekly highlight** (from the orb, or "This week’s highlight" in search) turns a week's tasks into one text to paste into the company's Copilot: a prompt, then the tasks. It opens on this week so far (Monday to today) with the **Standard** preset, so the usual export is the orb, Highlight, **Copy** (three clicks). Nothing is sent anywhere; Copy only puts the text on the clipboard. The range steps by whole Monday-to-Sunday weeks (‹ ›, with the current week ending today; "This week" comes back) or takes any two days. The prompt is a preset's body, editable for this export only ("Undo changes", or "Save as a preset"), then the **base block**: write a weekly highlight for the range, the shape (at most a number of bullet points and at most a number of words, both caps rather than targets, or a single sentence of at most that many words for a preset that asks for one, so One-liner isn't also asked for bullets), lead with what was achieved, plain past tense, no filler, combine small tasks, invent nothing. **Bullet points at most** (3) and **Words at most** (500) fill `{{max_items}}` and `{{word_limit}}`; `{{week_range}}` reads "19–25 Oct 2026". The prompt's words and dates are English whatever the browser's language. The tasks are what was done in the range (events too), oldest first, then, with **Include tasks in progress**, what is Working or Waiting now in active projects, in your project order. Each is a line like `- Done | Rotate keys | Project: Wards (Security) | Done Fri 23 Oct | Outcome: …`, leaving out what's empty. The built-in presets are Standard, Impact-first, Shipped + in-flight (which ticks Include tasks in progress), Plain language and One-liner. They live in the code, not your data, so they can be improved; **Duplicate** one to change it. Your own presets (name, body, bullet points or one sentence) are kept in your data; one marked **Share with my team** shows in the picker of anyone who has your file in their Team, as "For the council · Alice", with **Copy to mine**. Theirs is never changed. Your file holds every preset either way, since it's your backup; unshared ones just don't show to teammates.
- **Outcome.** A finished task takes a one-line outcome (what came of it), in the open task under its notes or straight in the Highlight's task list, where the panel counts the ones still missing. Ticking a task done offers **Add an outcome** in the toast, which opens the task with the field ready. The highlight lists it as `Outcome: …`.
- **Urgent deadlines** in the Timeline are filled in the theme's primary colour, so they stand out from the rest of the month; a small legend explains the marks.
- **Domains** group projects, such as areas of work, and are made by dragging in the Overview's project list. Drop one project onto the middle of an uncategorized one and the two become a new domain, whose name is then ready to type. Drag a project anywhere else to move it: between two projects (a line with a dot and "Drop here" shows where), onto a domain's name (first in it), or into the "Drop here" slot each group shows while you drag (last in it), including **Uncategorized** to take it out of its domain. The **+** beside "Projects" opens a small menu: **New project** or **New domain** (an empty one, named straight away, to drag projects into). **+ project** at the end of the list makes a project too. A domain's name renames on a double-click (or its pencil); its bin deletes it (with undo), leaving its projects uncategorized. From the keyboard, **Alt+↑ / Alt+↓** on a project moves it one place, into the next domain at a group's edge. Once there is a domain, the Board's lanes and View as also show projects under their domain's name, in the order the domains were made, uncategorized last, and search shows each project's domain. Without domains nothing changes.
- **Project order** is yours: drag a project in the Overview's list (across domains too), or a lane by its name on the Board (within its domain) (a long press on touch), and both follow. Archived and completed projects keep their places, and the list can't be reordered while it's filtered.
- **Projects can be marked done.** A done project leaves Needs attention and the numbers, its deadline stops counting, and it moves to "Completed" in the sidebar. Its tasks are left as they are. Reopen it any time.
- **Notes** sit at the top of an open task.
- **Renaming:** double-click a task's or a sub-task's name. Only the checkbox ticks either one done; clicking a sub-task's name does nothing, and a task's name opens it.
- **Resources** are added through a small form (title, link, optional note) that opens from the dashed "Add a resource…" row. A link with no title gets one from its path. Pasting "Title https://…" into the title field is split for you.
- **Long text** wraps or truncates with "…" (the full text shows on hover). Every single-column grid uses `minmax(0, 1fr)`, so nothing pushes the layout apart.
- **View mode** (Overview/Timeline) is remembered per browser under `magica:v1:mode`. It isn't part of the data or its exports. Settings, Team, the Observatory and View as are reached from the orb and aren't remembered.
- **Storage is IndexedDB.** The data is the same JSON as before, kept as one record in the browser's database `magica`. The first time a browser opens this version, whatever was in `localStorage` is copied across and the old copy is left untouched as a backup; Settings shows when that happened. If IndexedDB is missing or refuses (some private modes), the tracker uses `localStorage` exactly as before. Tabs keep each other up to date either way. A record that can't be read is set aside under a `corrupt:` key and never overwritten.
- **Settings** (from the orb) holds the theme, the allocation period and limit, your working days, your name, and storage: where the data lives, the export reminder, Export now, and **Wipe everything**, which downloads a backup first and keeps your name and settings.
- **Your name** (Settings) goes on your exports as `owner`, with an id that stays the same when you rename yourself, so a team leader can match your file to you.
- **Team.** Add people one at a time (name, optional role); there are no accounts and no server. Ask each person to Export, then bring their files in with **Import their files** (several at once). Each file is matched to a member by the profile id on it, or else by name; you can change the match, add the person, or skip the file before anything is kept. A newer file replaces that person's copy; an older or identical one is skipped; your own export (once you have set your name) is spotted and skipped. Their data is kept read-only in its own record (`team`), beside yours, and never goes into your exports. A file older than 7 days is flagged.
- **View as** (from Team, the Observatory or search) shows a member's tracker from their latest file, read-only: the same At a glance card as yours (open, in progress, waiting, overdue, each opening its list; their "may be escalated" flags show on their tasks and in the Observatory), their allocation by their own period and limit, and their active projects, with an Overview/Timeline switch like your own. Their Timeline is your month calendar over their deadlines; a day opens a panel listing them, with nothing to change. *First version (prototype):* it doesn't yet show their backlog, sub-tasks, notes or resources.
- **Allocation** (from the orb, or "Allocation" in search) is your load over time: this period, your average and how often you went over capacity or past your limit, then one column per week or fortnight (the last 12, from when you first allocated anything) against lines at 100% and your limit. Picking a column shows what filled that period, grouped by domain (a project with no domain is its own group; events are one group), largest first: each group's share and a bar, opening (one at a time, or "Show every task") to its tasks, with each task's project, when it was done ("Done 24 Sep, due 18 Sep" when late; "spread" when a start date spreads it) and its share; a task opens from there. It is worked out from your tasks as they are now, by the same rules as the bar, so nothing extra is saved: finished work stays where it counted, open work that is late or undated counts in this period only, and a deleted task, or a changed allocation, changes the history too.
- **Observatory** is the leader's view: everyone (you live, others from their files) with their allocation against their own limit (lowered by their days off), past-limit (and "past it N of the last M" when it keeps happening), waiting work, old files, who is on leave today and timesheet months that don't add up flagged, and every "I may be escalated" flag in one list. Each row's **Earlier weeks** or **Earlier fortnights** (closed until you open it) lists the 5 periods before this one, newest first: the dates, how many tasks filled it, and its bar against their limit, under a line saying whose it is, how often they went past the limit, and which file it comes from. On your own row it links to the Allocation screen. *First version (prototype):* the layout and what it summarises are expected to change.
- **Schema version 8.** Version 8 only added optional fields: `outcome` on tasks, and `highlightPresets` on the root (`id`, `name`, `body`, `format` `bullets` or `sentence`, `shared`, `createdAt`, `updatedAt`). Every v7 file loads as-is through `MIGRATIONS[7]`. A merge import adds the other file's presets like its domains (the newer copy wins). Sample data gives two done tasks an outcome, and Alice's file a shared preset and one she keeps to herself.
- **Schema version 7.** Version 7 only added optional fields: `costCenters` on the root (`id`, `code` and/or `name`, `createdAt`, `updatedAt`), `costCenterId` on projects, and `costCenterId` on each timesheet month (where those days are charged). Every v6 file loads as-is through `MIGRATIONS[6]`. A merge import adds the other file's cost centers like its domains (the newer copy wins). Sample data adds three cost centers (one known only by its name) and leaves the Familiar Registry without one.
- **Schema version 6.** Version 6 only added optional fields: `calendar` on the root (entries with `kind` `event`, `leave` or `holiday`, `title`, `date`, and optionally `until`, `time`, `effort`, `done`/`doneAt`, `notes`), `timesheet` on projects (`month` like `"2026-10"` and whole `days`, one entry per month), `archivedAt` on projects (when it was archived; projects archived earlier have none and count as long ago), and `workdays` in the settings (`from`, and `weekdays` as 1 for Monday to 7 for Sunday). Every v5 file loads as-is through `MIGRATIONS[5]`. A merge import adds the other file's calendar entries like its projects (the newer copy wins); a project's timesheet comes with its copy. Sample data adds events, a holiday, leave and timesheet days (a balanced last month, this month two days short) to sample projects, and the sample teammates include one on leave today and one a day short last month; your settings are never touched.
- **Schema version 5.** Version 5 only added optional fields: `domains` on the root (`id`, `name`, `createdAt`, `updatedAt`), `domainId` on projects, and `unit` (`percent` or `hours`) in `settings.allocation`; and `effort` may now be a fraction of a percent. Every v4 file loads as-is through `MIGRATIONS[4]`. A merge import adds the other file's domains like its projects (the newer copy wins).
- **Schema version 4.** Version 4 gave every task a `status` (`todo`, `working`, `waiting`, `done`; `todo` when missing) and replaced `blocked` with `waiting` (`since`, `on`). `MIGRATIONS[3]` works each v3 task's status out from what it says: done, blocked (keeping since when and on what), a sub-task done (Working), or To do. `done` stays beside the status and is kept in step with it, because the completion rule decides Done. An older build refuses a v4 file rather than dropping statuses it doesn't know.
- **Schema version 3.** Version 3 only added optional fields: on tasks `startsOn`, `definitionOfDone`, `relatedPeople`, `blocked` (`since`, `blocker`) and `escalation` (`since`, `by`, `why`); on projects `definitionOfDone` and `relatedPeople`; on the root `owner` (`id`, `name`) and `settings.allocation` (`period`, `maxLoad`). Every v2 file loads as-is through `MIGRATIONS[2]`.
- **Schema version 2.** Version 2 only added optional fields: deadlines, priority, effort, project `doneAt`, and backlog `updatedAt` (so a merge can tell which copy of an edited backlog item is newer). Every v1 file and v1 browser storage loads as-is through `MIGRATIONS[1]` and is saved back as v2 on the next change. The version bump means an older build refuses a v2 file instead of silently dropping fields it doesn't know. The storage key stays `magica:v1`: it names the storage slot, not the schema.
- **Unsafe URL schemes** (`javascript:`, `data:`, `vbscript:`, `blob:`) are rejected on save and on import. Bare hosts like `docs.example.com/x` get `https://` added.
- **Ids** use `crypto.randomUUID()` where available. Over plain http on a LAN it isn't, so ids fall back to `crypto.getRandomValues`.
- **Themes.** Settings → Appearance (or "Theme: …" in search) picks the colours: **Euphie** (the default), **March 7th** and **Firefly** (each light and dark, with System / Light / Dark), **Lavender haze** and **Peach milk** (light), **Moonlit cloud** (dark), and **Magica classic**, the original palette, unchanged. The choice is remembered per browser under `magica:v1:theme`, like the view mode, and isn't part of the data or its exports. With System, the theme follows the device's light or dark setting as it changes. Each theme's own highlight colour (Euphie's hairpin yellow, March 7th's icy blue, Lavender's blush…) is what marks things worth watching: deadlines, overload, untouched tasks.
- **Contrast.** In every theme, body text, coloured text and text on tints keep at least 4.5:1 (checked when the palettes were made). Faint metadata (done items, dates) sits around 3:1 and is never the only way something is shown. Pale primaries (Euphie, March 7th, Peach) carry dark labels, and a deeper shade of the primary draws bars and thin marks. In Magica classic, Steel (#7A9AB5) is 2.7:1 on Mist and used only for metadata and done items, and "worth watching" is a Gold pill with dark text (7.4:1), with Burnished for the dot only.
- **Small deletions** (sub-tasks, resources, backlog items) happen at once with an Undo toast. Deleting a project or task, unticking a parent, and demoting a task that loses sub-tasks or resources all ask first.
